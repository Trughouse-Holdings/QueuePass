# UI Contract: Customer Parity Checklist

**Feature**: `040-rust-customer-app` | Spec FR-012 to FR-015, FR-020, SC-002

The Rust Customer app MUST do everything on this list the way the React Customer app does on `main`
(`680b4f7`, plus anything merged before the implementation PR opens, added to this list by that
PR). "The same" means the same requests, the same Backend refusals shown with the same meaning in
the same place, the same values kept after a refusal, the same figures, the same timings, and the
same visible words. It loads the React app's own stylesheets (`packages/shared/src/web/theme.css`,
then `customer-app/src/styles.css`), then the Rust Admin app's `../admin-rust-app/style/red.css` last (linked, not copied), so the element
structure and class names MUST be the same too. Accessible names (labels, headings, button and link
text, `aria-label`s) MUST be the same, so the `@customer` browser journeys drive both apps. **Only
the colors (red) and the app's name ("QueuePass Tickets (Rust)") differ.** The layout is the same
(FR-020): the same pages and paths, the same headings, cards, sections, fields, buttons, and lists
in the same order and arrangement, and the same phone-width behavior (SL rows). It signs in to the
same realm, `queuepass-customer-app`, through its own client `customer-rust-app`, so customers,
orders, tickets, and reservations are the same ones the React app shows, and one Keycloak session
serves both.

The React Customer app's source is the reference. Where this list and the React Customer app
disagree, the React Customer app wins, and this list is corrected in the implementation PR. Quirks
of the React app named below are copied, not fixed, so the two apps stay the same; a fix belongs in
a React change first. The implementer works through the React source file by file (the "Source"
column; paths are under `customer-app/src/` unless they start with `packages/` or `customer-app/`)
and ticks each item in the implementation PR, marking how it was checked: **E** (browser test,
named), **U** (unit test in `core`), **M** (checked by hand, with the date), or **N/A** (only where
a row says it can't occur in the Rust app, with the reason). Texts in quotes are
exact: `…` is one character (U+2026), apostrophes are straight (`'`), and `–` in price ranges is an
en dash (U+2013). Every page loads its data with the customer's own token (`useLoad`: 2xx → shown;
401 → sign in again; 404 → the page's "no longer available" text; anything else or no answer →
"Can't reach the QueuePass service."), unless a row says otherwise.
