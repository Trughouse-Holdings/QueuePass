# Data Model: Rust Admin App

**Feature**: `037-rust-admin-app` | **Date**: 2026-11-11

## Persistent data

**No change.** No Prisma model, migration, or OpenAPI schema is added or changed. The Rust Admin
app reads and writes the same venues, seating layouts, events, ticket tiers, images, orders,
tickets, and check-ins as the React Admin app, through the same API (spec Key Entities).

## Rust Admin app internal model (in memory only)

These types live in the app's `core` library (research R9). They are not stored anywhere.

| Type | Holds | Notes |
|---|---|---|
| `AuthState` | `SignedOut`, `SigningIn`, `SignedIn { tokens, username, roles, expires_at }`, `RenewFailed`, `WrongRole`, `Unreachable` | tokens in memory only; transitions mirror `auth-provider.tsx` |
| `PkceStore` | the one-time PKCE verifier and `state` across the sign-in redirect | a trait: `sessionStorage` in the browser, in memory in tests; emptied right after the code exchange |
| `ApiError` | `status`, `code`, `message`, `details` | the contract's one error shape; `details` drives the field placement of refusals |
| API types | generated by `typify` from `components.schemas` | rebuilt on each build (R5) |
| `EventFormState` | each field's local value (`YYYY-MM-DDTHH:mm` per time field, as in 036), doors mode, ticket types, section-to-type map, limit, pending images, touched fields | the ported `event-form-checks` and `event-form-times` work on it |
| `VenueFormState` | address fields, time zone, capacity, section lines | |
| `SeatState` | per seat `Open`, `Held`, `Sold` | updated from the seat stream |
| `ExportTable` | title, made-at instant, columns (name, kind: text, number, money, date-time), rows | one builder per report, three writers (R7) |

### State transitions: `AuthState`

```text
SignedOut ──start──▶ SigningIn ──code exchanged, has role──▶ SignedIn
                         │                                     │  ▲
                         └──no queuepass-admin role──▶ WrongRole│  │ renewed
                                                               ▼  │
                                                          (near expiry) ──refresh fails──▶ RenewFailed
                                                                                      │ retry ok ─▶ SignedIn
                                                                                      │ refused  ─▶ SigningIn
SignedIn / WrongRole / RenewFailed ──sign out──▶ end-session redirect ──▶ SignedOut
any ──Backend unreachable on load──▶ Unreachable (retry offered)
```
