# UI Contract: Admin Parity Checklist

**Feature**: `037-rust-admin-app` | Spec FR-012 to FR-015, FR-020, SC-002

> **2026-11-14** (spec Clarifications): rewritten before any implementation, from the React Admin
> app's code on `main` at `ff993c4`, so it is complete for that version: seat maps (`038`, rows
> M1–M17), the layout editor (`039`, rows LE1–LE81), and the "Same layout" rows (SL1–SL14) are added, and every
> other row is checked against the code and made exact. The first version's rows were written from
> the specs and allowed the layout to differ.

The Rust Admin app MUST do everything on this list the way the React Admin app does on `main`
(`ff993c4`, plus anything merged before the implementation PR opens, added to this list by that
PR). "The same" means the same values saved, the same Backend refusals shown with the same meaning
in the same place, the same values kept after a refusal, the same figures, and the same visible
words. Accessible names (labels, headings, button text) MUST be the same, so one set of browser
tests drives both apps (research R10). **Only the colors (red, research R8) and the app's name
("QueuePass Admin (Rust)") differ.** The layout is the same (FR-020): the same pages and paths, the
same headings, cards, sections, fields, buttons, and table columns in the same order and
arrangement, and the same phone-width behavior (SL rows).

The React Admin app's source and its merged specs are the reference. Where this list and the React
Admin app disagree, the React Admin app wins, and this list is corrected in the implementation PR.
Quirks of the React app named below are copied, not fixed, so the two apps stay the same; a fix
belongs in a React change first. The implementer works through the React source file by file (the
"Source" column; paths are under `admin-app/src/` unless they start with `packages/`) and ticks
each item in the implementation PR, marking how it was checked: **E** (browser test, named), **U**
(unit test in `core`), or **M** (checked by hand, with the date). Every `confirm` is
`window.confirm`.
